# Nexora ERP API

Laravel 12 REST API for the Nexora ERP MVP. It uses Laravel Sanctum bearer tokens and a MySQL database; SQLite in-memory is configured for the feature tests.

## Requirements

- PHP 8.3 or newer with `pdo_mysql`, `mbstring`, `openssl`, `tokenizer`, `xml`, `ctype`, `fileinfo`, and `json`
- Composer 2
- MySQL 8+

## Setup

From `Backend/`:

```powershell
composer install
Copy-Item .env.example .env
php artisan key:generate
```

Set `DB_DATABASE`, `DB_USERNAME`, and `DB_PASSWORD` in `.env`. Run the Laravel migration (recommended):

```powershell
php artisan migrate
```

Alternatively, execute [`database/nexora_erp.sql`](database/nexora_erp.sql) directly in MySQL instead of running the migration. Do not apply both to the same database.

Set `ADMIN_EMAIL` and `ADMIN_PASSWORD` in `.env`, then create or update the first administrator:

```powershell
php artisan db:seed
```

Run the API:

```powershell
php artisan serve
```

Run the feature tests in another terminal:

```powershell
php artisan test
```

Laravel API endpoints are prefixed with `/api/v1`. Use `POST /api/v1/login` to receive a bearer token and send it as `Authorization: Bearer <token>`. Public registration always creates an employee; only an administrator can assign elevated roles.

## API areas

- Authentication: register, login/logout, password reset/change, profile
- CRM and catalog: customers, products, categories, search/filter/pagination
- Sales: orders and constrained status transitions; stock is deducted on completion
- Finance: invoices generated from confirmed orders and payments checked against locked invoice balances
- Inventory: stock movements, history, low-stock reporting
- Business overview: dashboard, sales/product/customer/finance reports
- Administration: users, roles, audit logs
- System settings: administrator-managed key/value settings by group
- Notifications: in-app notification list and read state

Amounts use `DECIMAL(12,3)` to support TND precision. Order and invoice numbers are generated by the API. The daily overdue-invoice job is registered in Laravel's scheduler; run `php artisan schedule:work` locally or configure Laravel's scheduler in production.

For inventory movements, `in` and `out` use `quantity` as the movement size; an `adjustment` uses it as the new target stock, including zero; and `transfer` records a move between two named locations without changing total on-hand stock.
